МVP для Changellenge Hack&Change 2026: веб-чат и автономный скрипт сабмита на **одном и том же движке RAG**, который отвечает на вопросы по предоставленной базе нормативных документов, приводит ссылки на пункты и обоснованно сообщает о недостатке данных. Визуально ориентирован на выбранные командой макеты LEX: тёмно-синий сайдбар, светлая рабочая область, карточки ответов и правая панель источников.

## Запуск одной командой

Требуются Docker и Docker Compose. Участникам нужен **только ключ DeepSeek**, другие LLM не используются.

```bash
cp .env.example .env
# В .env заполнить DEEPSEEK_API_KEY=...
docker compose up --build
```

После запуска откройте **http://localhost:8000**. Проверка состояния API: **http://localhost:8000/api/health**.

При публичном размещении с платным API-ключом задайте также `DEMO_ACCESS_CODE` — пароль доступа к генерации, который интерфейс запросит у посетителя. Это минимальная защита от несанкционированного расходования API-баланса, но не полноценная система аутентификации.

Без API-ключа интерфейс и просмотр 21 документа работают, а генерация ответов корректно возвращает ошибку «Не задан DEEPSEEK_API_KEY». Это намеренное поведение: приложение не выдаёт имитацию ответа нейросети за настоящий результат.

### Локальный запуск без Docker

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
# Установите DEEPSEEK_API_KEY в переменных окружения или запустите через оболочку с `set -a; source .env; set +a`
uvicorn app:app --host 127.0.0.1 --port 8000
```

`uvicorn` не загружает `.env` автоматически. В Docker Compose значения `.env` передаются контейнеру через `env_file`.

## Основные экраны

1. **Новый диалог** с типовыми юридическими вопросами.
2. **Ответ с источниками**: маркеры `[1]`, `[2]`, название документа, пункт и извлечённый фрагмент.
3. **Просмотр оригинала** из базы знаний, с подсветкой искомого пункта.
4. **База знаний** с поиском по номерам, контрагентам, названиям, категориям.
5. **Уточнения и обоснованные отказы**, если недостаточно оснований.

История диалогов хранится только в браузере пользователя (`localStorage`); на сервере она не сохраняется. Для демонстрации используйте только тестовые персональные данные.

## Архитектура

```text
       Веб-чат (FastAPI + SPA)       solution.py (CSV)
                        \           /
                         LegalAssistant
                   вопрос + история + дата
                                |
                      локальный поиск BM25
                точные номера / контрагенты / редакции
                                |
                      21 TXT-документ в ZIP
                                |
             DeepSeek API (или прокси организаторов)
                                |
            ответ с [1], [2] → проверка реальных ссылок
                                |
                       ответ / уточнение / отказ
```

- **Одна модель**: `DEEPSEEK_MODEL=deepseek-flash` для самостоятельного запуска; во время автоматической проверки использовать `LLM_MODEL` из среды организаторов (**DeepSeek V4.1 Flash**). Идентификатор платформенной модели намеренно не жёстко прописан.
- **Поиск**: лексический BM25, словарное выравнивание юридических формулировок, точные идентификаторы договоров и контрагентов. Приоритет за проверяемой связью с документами, а не за сложностью векторной системы.
- **Редакции**: отдельные регламенты 2023/2025 и временная фильтрация; в ответах на вопросы об изменённом адресе учитывается доп. соглашение и дата спецификации.
- **Защита**: содержимое документов используется как недоверенные данные. Из модельного контекста удалена явная prompt injection из служебной записки о 90 днях. Внешний интернет не используется для обоснования.
- **Проверка**: модель может ссылаться только на пронумерованные фрагменты из текущего запроса; фиктивные номера ссылок отбрасываются, ответ без валидной ссылки не объявляется подтверждённым. Это проверка существования ссылок, не полноценная математическая проверка логического следования каждого утверждения.

## Эндпоинты

| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/health` | Доступность и настройки модели без раскрытия ключа |
| GET | `/api/documents` | Список документов (`q`, `category`) |
| GET | `/api/documents/{id}` | Полный исходный текст TXT |
| GET | `/api/search?q=...` | Поиск подтверждающих фрагментов |
| POST | `/api/chat` | `{"question":"...","history":[{"role":"user","content":"..."}]}` |

Формат ответа `/api/chat`:

```json
{
  "status": "answered",
  "answer": "... [1]",
  "sources": [
    {"ref": 1, "doc_id": "doc-...", "title": "...", "clause": "п. 4.2", "excerpt": "...", "version": null, "chunk_id": "..."}
  ]
}
```

Возможные `status`: `answered`, `clarify`, `insufficient`. При временном недоступном DeepSeek — HTTP 503; поддельный ответ не формируется.

## Автоматический сабмит Hack&Change

**Регламент**: скрипт в корне ZIP, вход `DATA_DIR/questions.csv` (`id,question`) + `DATA_DIR/knowledge-base.zip`, выход `submission.csv` (`id,answer`). Данные и API-ключи в ZIP не включаются; файлы должны лежать в корне. Зависимости ограничены разрешёнными организаторами: `fastapi`, `uvicorn`, `pydantic`, `httpx`.

Собрать ZIP:

```bash
python scripts/package_submission.py
```

Получится `lex_submission.zip` с файлами: `solution.py`, `engine.py`, `requirements.txt`. Во время проверки платформа предоставит `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `DATA_DIR` автоматически. Скрипт обращается к `/chat/completions` и создаёт непустой ответ для каждого `id` с CSV-экранированием, но не сохраняет состояния между тест-кейсами.

Локальная проверка формата:

```bash
cp data/demo_questions.csv data/questions.csv
# Экспортируйте DEEPSEEK_API_KEY или LLM_API_KEY в окружение
python solution.py
head -n 3 submission.csv
```

Ограничения платформы: 5 сабмитов за день, ZIP до 128 МБ, 8 CPU/16 ГБ RAM, выполнение до 20 минут. Короткие ответы до 150 слов предпочтительны. В текущей реализации вопросы обрабатываются последовательно; при большом скрытом наборе тестов это может потребовать оптимизации по времени.

## Тесты

```bash
pip install pytest
pytest -q
```

Покрыты загрузка базы, различение контрагентов, поиск пунктов 4.1/4.2, редакции 2023/2025, дополнительное соглашение, санкционная проверка, защита от инъекции, короткий диалог, проверка маркеров источников и API без ключа.

## Ограничения и дальнейшие шаги

- Без реального DeepSeek API и тестового набора организаторов нельзя гарантировать точность ответа на скрытых вопросах или скорость проверки; поэтому по умолчанию показаны только реально реализованные возможности.
- Подтверждение существования источника не доказывает юридическую правильность логического вывода: при наличии времени добавьте второй проход проверки фактических утверждений DeepSeek и ручной аудит экспертами.
- Законы представлены только в доступной редакции; для вопроса о прошлом периоде, если тогда действовала другая редакция, ассистент должен объяснить ограничение.
- Новая загрузка пользовательских документов, админка, подписки, биллинг и полноценное сравнение версий **не входят** в MVP.
- Не публикуйте действительные API-ключи в `.env`, логах или репозитории.

## План команды на 2 дня

- **День 1:** аналитик 1 — каталог документов, редакции и тестовые источники; аналитик 2 — матрица сценариев, golden answers; разработчик — индекс, RAG, DeepSeek и `solution.py`.
- **День 2:** тестирование и фиксы, UI с источниками, Docker/README, первые сабмиты, презентация и демонстрация: ответ → источник → пункт документа → обоснованный отказ.

## Публикация как нового публичного GitHub-репозитория

Проект уже опубликован в публичном репозитории: **https://github.com/Ryt1nger/ou**. Команды ниже — только для самостоятельного создания другого репозитория:

```bash
git init -b main
git add .
git commit -m "Initial LEX legal assistant MVP"
gh repo create lex-psb --public --source=. --remote=origin --push
```

Для последней команды нужен установленный и авторизованный GitHub CLI (`gh auth login`). Если репозиторий уже создан через веб-интерфейс GitHub, вместо последней команды укажите его адрес: `git remote add origin <URL>` и `git push -u origin main`. Перед любым push убедитесь, что `.env` не отслеживается: `git status --short`.

Официальный формат API и модель `deepseek-flash`: https://api-docs.deepseek.com/api/create-chat-completion/ .

## Где вводить DeepSeek API-ключ

Пошаговая инструкция для локального запуска и хостинга: [docs/DEEPSEEK_KEY.md](docs/DEEPSEEK_KEY.md).

**Не загружайте `.env` в публичный репозиторий.** Для быстрого просмотра дизайна без ключа доступен автономный интерактивный прототип `index.html` в корне GitHub — в нём ответы тестовые и DeepSeek не вызывается.

## Финальная сдача

- [SUBMISSION_LINKS.txt](SUBMISSION_LINKS.txt) — файл с GitHub-ссылкой и местом для ссылки на PDF-презентацию в Google Диске.
- [SUBMISSION_CHECKLIST.md](SUBMISSION_CHECKLIST.md) — полный список требований, обязательных проверок и план первого слайда презентации.

**Важно:** корневой `index.html` — самостоятельный интерактивный *макет*. Настоящий веб-чат с юридическими ответами запускается через FastAPI и DeepSeek; GitHub Pages не запускает Python. Без реального ключа DeepSeek и прогонки Docker нельзя утверждать, что все интеграции проверены. Для финальной сдачи по кейсу всё ещё требуется PDF-презентация со ссылкой на репозиторий и порядком проверки на первом слайде.

## Демо на GitHub Pages

Отдельная ветка [`gh-pages`](https://github.com/Ryt1nger/ou/tree/gh-pages) уже содержит только статический интерактивный прототип. Чтобы GitHub включил сайт, откройте [Settings → Pages](https://github.com/Ryt1nger/ou/settings/pages), выберите **Build and deployment → Deploy from a branch → gh-pages → /(root)** и нажмите Save. После появления статуса Published ожидаемый URL: https://ryt1nger.github.io/ou/ . Пока статус Published не проверен, URL нельзя считать работающим.

Это лишь интерфейс с подготовленными ответами, а не полноценный backend. Для интерактивного DeepSeek нужен сервер (Render/Vercel) и `DEEPSEEK_API_KEY` в защищённых переменных окружения хостинга, **не в GitHub**.
